# CLI reference

The `presto` CLI is auto-generated by [pydantic-settings'](https://docs.pydantic.dev/latest/concepts/pydantic_settings/) `CliApp` from the same Pydantic models that drive the YAML schema (see **[Settings reference](settings-reference.md)**). Every field of `WorkflowSettings` is exposed as a dotted-option flag like `--parameterisation-settings.molecules`.

The captures below come from `presto <cmd> --help` and may be slightly out of date — when in doubt, run `--help` yourself.

## Synopsis

```text
presto version              # print the installed version and exit
presto train [OPTIONS]      # train with command-line arguments
presto train-from-yaml PATH # train from a YAML settings file
presto write-default-yaml PATH  # write a starter YAML
presto clean PATH           # remove generated outputs but keep the YAML
presto analyse PATH         # regenerate diagnostic plots without re-running
```

## `presto version`

```text
usage: presto version [-h]

Print the version of presto and exit.

options:
  -h, --help  show this help message and exit
```

## `presto train`

The big one. Runs the full workflow from CLI flags. All `WorkflowSettings` fields are exposed as dotted options; for example, `WorkflowSettings.parameterisation_settings.molecules` becomes `--parameterisation-settings.molecules`. Nested settings classes (`mlp_settings`, `msm_settings`, …) follow the same pattern.

The minimum required flag is `--parameterisation-settings.molecules` — every other field has a default.

Quick examples:

```bash
# minimal: one SMILES, defaults for everything else
presto train --parameterisation-settings.molecules "CCO"

# pick a non-default MLP for training-sampling
presto train --parameterisation-settings.molecules "CCO" \
    --training-sampling-settings.mlp-settings.ml-potential aimnet2

# congeneric series
presto train --parameterisation-settings.molecules "CCO,CCC"
```

For SDF inputs, see **[Use SDF inputs](../how-to/use-sdf-inputs.md)**.

For the full flag list (long — over 80 options), run:

```bash
presto train --help
```

The flags are grouped by settings class:

- `--version`, `--output-dir`, `--device-type`, `--n-iterations`, `--memory` — top-level `WorkflowSettings` knobs.
- `--parameterisation-settings.*` — molecule input, initial force field, harmonics linearisation, MSM settings (`msm-settings.*`), and type generation settings (`type-generation-settings.*`).
- `--training-sampling-settings.*` — sampling for training data. Includes nested `mlp-settings.*` and protocol-specific flags (metadynamics bias, torsion-minimisation knobs).
- `--testing-sampling-settings.*` — same shape as training, but for the test set.
- `--training-settings.*` — optimiser, learning rate, epochs, regularisation.
- `--outlier-filter-settings.*` — outlier-rejection thresholds.

The `--training-sampling-settings.sampling-protocol` and `--testing-sampling-settings.sampling-protocol` flags accept one of:

- `mm_md`
- `ml_md`
- `mm_md_metadynamics`
- `mm_md_metadynamics_torsion_minimisation` (default for training)
- `pre_computed`

See **[Concepts → Sampling protocols](../concepts/sampling-protocols.md)** for what each does.

## `presto train-from-yaml`

```text
usage: presto train-from-yaml [-h] [SETTINGS-YAML]

Run the training process with arguments read from a YAML file.

positional arguments:
  SETTINGS-YAML  Path to the YAML settings file for training (default:
                 workflow_settings.yaml)

options:
  -h, --help     show this help message and exit
```

Generate a starter YAML with `presto write-default-yaml` (next), edit the molecule input(s), then run `train-from-yaml`. The YAML produced at the end of a run can be replayed verbatim.

## `presto write-default-yaml`

```text
usage: presto write-default-yaml [-h] [FILE-NAME]

Write a default YAML file for the training settings.

positional arguments:
  FILE-NAME   The name of the default YAML settings file to write (default:
              workflow_settings.yaml)

options:
  -h, --help  show this help message and exit
```

The written file contains a placeholder `CHANGEME` under `parameterisation_settings.molecules`. Edit it (and any other fields you want to change) before running `train-from-yaml`. See **[Settings reference](settings-reference.md)** for the full YAML shape.

## `presto clean`

```text
usage: presto clean [-h] [SETTINGS-YAML]

Clean the output directory by removing generated files.

positional arguments:
  SETTINGS-YAML  Path to the YAML settings used for training (default:
                 workflow_settings.yaml)

options:
  -h, --help     show this help message and exit
```

Walks the expected output layout (see **[Concepts → Output directory layout](../concepts/output-layout.md)**) and deletes every file/directory `presto train` would produce. The settings YAML itself is preserved.

## `presto analyse`

```text
usage: presto analyse [-h] [SETTINGS-YAML]

Analyse the training data and results.

positional arguments:
  SETTINGS-YAML  Path to the YAML settings used for training (default:
                 workflow_settings.yaml)

options:
  -h, --help     show this help message and exit
```

Regenerates the diagnostic plots under `<output_dir>/plots/` from existing training output without re-running sampling or training. Useful when you want a fresh plot set after editing the trained `bespoke_ff.offxml`, or when plot generation crashed at the end of a run.

## Notes on dotted overrides

`pydantic-settings` flattens nested settings classes into dot-separated flags. The pattern:

```text
--<settings-class>.<sub-field>          ParentSettings.sub_field
--<settings-class>.<nested>.<sub-field> ParentSettings.nested.sub_field
```

Underscores in Python field names become hyphens in CLI flags. For example, `ml_potential` is exposed as `--mlp-settings.ml-potential`.

Boolean flags follow the `--flag | --no-flag` convention. Lists accept comma-separated values: `--parameterisation-settings.molecules "CCO,CCC"`.

Dict-shaped settings (e.g. `parameter_configs`, `type_generation_settings`) are awkward to specify on the CLI — prefer the YAML form for those.
